**A launch protocol for building Solana tokens with real liquidity and legs.**

The d4rth Launch Protocol (DLP) is a simple, repeatable way to launch a token so it has real depth from day one. It launches on a USDC pool, locks liquidity against the ecosystem's anchor token and SOL, and sets the token up as a hub other tokens can pair into. It works for any token. Fill in the blanks in [LAUNCH-ANY-COIN-TEMPLATE.md](LAUNCH-ANY-COIN-TEMPLATE.md) and go.

## The 6 steps
1. Launch on pump.fun paired with USDC. It's the strongest pool.
2. Dev buy about 20% of supply.
3. Pair (permanently lock) 10% with the ecosystem's anchor token on Meteora (DAMM V2).
4. Pair (permanently lock) 10% with SOL on Meteora.
5. The rest stays on USDC: the pump.fun curve, then PumpSwap after graduation.
6. **Then** partner tokens pair a chunk of their supply to it. It becomes the hub.

Plus: add GitHub `d4trhban3` as a creator-fee recipient (strongly encouraged, see below).

## Why 20%
- A pump.fun curve only sells about 79% of supply before it graduates. Big dev buys eat it.
- 10% side pools stay smaller than the USDC pool, so USDC stays the main pool.
- It leaves most of the curve to real holders.

## Support the protocol (strongly encouraged, not required)
This protocol came out of a lot of research and testing, and it's free and open. Creator fees are how you support it. If you launch with the d4rth Launch Protocol, please add GitHub **d4trhban3** as a pump.fun creator-fee recipient.

1. On pump.fun, find the creator-fee recipients option (at token creation, or in the coin's creator-fee settings).
2. Add a recipient by GitHub username: `d4trhban3`.
3. Pick a share you're comfortable with.

It's optional. Nothing breaks without it. It only works if creator fees stay on, not pump.fun's send-all-fees-to-holders switch. Holder rewards are still the point, so you can share a slice and still pay holders.
